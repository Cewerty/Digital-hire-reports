# Рабочее пространство наставника — frontend-прототип

Интерактивный прототип сценария:

> Профиль и интервью → Чтение отчёта → Правка → Утверждение документа.

Приложение работает полностью в браузере на вымышленных данных.

## Запуск

```bash
npm install
npm run dev
```

## Проверка

```bash
npm run verify
npm run build
```

`npm run verify` запускает проверку типов (`tsc -b --noEmit`) и Biome
(`biome check --write src`). ESLint и Prettier в проекте не используются.

## Маршруты

| Маршрут | Назначение |
| :--- | :--- |
| `/` | Дашборд куратора: профиль, очередь задач, лента событий |
| `/candidates` | Реестр кандидатов с фильтрами по этапу отбора |
| `/candidates/:id` | Профиль кандидата и материалы интервью |
| `/candidates/:id/report` | Просмотр сохранённого отчёта |
| `/candidates/:id/review` | Проверка, правка и утверждение отчёта |
| `*` | Страница «Не найдено» |

Демонстрационные идентификаторы: `c-01` (отчёт на рассмотрении), `c-02`
(утверждённый отчёт), `c-03` (не опрошен, без отчёта), `c-04` (отклонён,
интервью есть, отчёта нет).

Старые пути `/report` и `/review` перенаправляются на
`/candidates/c-01/report` для обратной совместимости.

## Демонстрационные состояния

Состояния загрузки и пустые состояния воспроизводятся через query-параметр
`state` на страницах профиля и отчёта, без изменения кода:

- `/candidates/c-01`, `/candidates/c-01/report` — обычный режим с
  демонстрационными данными;
- `/candidates/c-01?state=loading`,
  `/candidates/c-01/report?state=loading` — имитация асинхронной загрузки;
- `/candidates/c-01?state=empty`,
  `/candidates/c-01/report?state=empty` — пустые состояния: профиль кандидата
  и сохранённый отчёт отсутствуют.

Параметр `state` поддерживают только `ProfilePage` и `ReportPage`. Дашборд
куратора (`/`) и реестр (`/candidates`) его игнорируют.

Пустое состояние отчёта содержит переход в профиль. В профиле вместо карточки
кандидата и списка интервью показываются заглушки.

Пустые значения внутри отчёта проверяются в редакторе:

- очистите любой необязательный реквизит (например, «Куратор») и сохраните
  черновик — в отчёте отобразится «Не указано»;
- очистите текст раздела и переключитесь в «Предпросмотр» — отобразится
  «Раздел не заполнен»;
- если у раздела нет источников — «Источники раздела не указаны».

## Ограничения прототипа

- Нет сохранения между перезагрузками страницы.
- Нет backend, API, БД, LLM, интеграции с 1С.
- Нет авторизации.
- Нет отдельной формы решения «Принять / Отказать».
- Нет автоматической проверки согласованности статуса, выводов и вердикта.
- Данные кандидата имитируют импорт из 1С и доступны только для чтения.

## SPA fallback

Для корректной работы клиентских маршрутов при прямом открытии и перезагрузке
страниц используется SPA fallback на `index.html`. В Vercel это настраивается
через `vercel.json`:

```json
{
  "framework": "vite",
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

Параметры `framework`, `buildCommand` и `outputDirectory` продублированы в
`vercel.json`, чтобы сборка не зависела от ручных настроек проекта в панели
Vercel. `rewrites` применяются только к путям, для которых нет статического
файла в `dist`, поэтому ассеты отдаются напрямую.
