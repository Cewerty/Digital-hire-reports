# Архитектура frontend-прототипа рабочего пространства наставника

## 1. Обзор

Прототип реализует сценарий:

> Профиль и интервью → Чтение отчёта → Правка → Утверждение документа.

Приложение работает полностью в браузере на вымышленных данных.  
Backend, API, БД, LLM, интеграция с 1С и авторизация отсутствуют.

## 2. Стек

- Vite
- React
- TypeScript (строгий режим)
- React Router
- Tailwind CSS
- shadcn/ui
- `@tailwindcss/typography`
- `react-markdown`
- `lucide-react` — по необходимости

## 3. Маршруты

| Маршрут | Страница | Назначение |
| :--- | :--- | :--- |
| `/` | `ProfilePage` | Профиль кандидата и материалы интервью |
| `/report` | `ReportPage` | Просмотр сохранённого отчёта |
| `/review` | `ReviewPage` | Редактирование и утверждение |
| `*` | `NotFoundPage` | Страница «Не найдено» |

Используется клиентская навигация без перезагрузки страницы.

## 5. Состояние

### Сохранённая версия

Хранится в `main.tsx` через `useState<CandidateReport>` или `useRef<CandidateReport>`.

`useRef` может применяться, если это улучшает производительность — например, чтобы не пересоздавать роутер при каждом обновлении отчёта. В этом случае роутер получает актуальное значение через callback-геттер, а обновление отчёта не вызывает re-render корневого `App`. Страницы всё равно получают актуальные данные через loader data.

Роуты создаются в main.tsx. Данные и callback могут передаваться в страницы двумя способами:

- через props элемента страницы;
- через loader data, если это улучшает производительность (например, при ленивой загрузке страниц через `lazy`).

Context не используется.

Используется для:

- просмотра документа;
- отображения состояния документа;
- начального заполнения редактора.

### Рабочая копия

При открытии `/review` создаётся независимая копия сохранённого отчёта.

```text
Сохранённый документ
        ↓ открыть редактор
Рабочая копия
        ↓ ввод
Меняется только рабочая копия
        ↓ сохранить / утвердить
Обновляется сохранённый документ
```

Вложенные объекты и массивы исходного отчёта не мутируются.

### Переходы

| Действие | Сохранённый документ |
| :--- | :--- |
| Открыть редактор | Не меняется |
| Ввести текст | Не меняется |
| Переключить предпросмотр | Не меняется |
| Отменить / уйти без сохранения | Не меняется |
| Сохранить черновик | Обновляется, состояние `draft` |
| Утвердить | Обновляется, состояние `approved` |

Открытие утверждённого документа в редакторе не снимает утверждение.  
Сохранение новой версии как черновика снимает утверждение предыдущей версии.

## 6. Поток данных

1. `main.tsx` хранит `CandidateReport` (через `useState` или `useRef`) и передаёт его в страницы через props или loader data.
2. `ProfilePage` получает `candidate` и `interviewEntries` из демоданных.
3. `ReportPage` получает `report` и отображает его через `ReportDocument`.
4. `ReviewPage` при монтировании создаёт рабочую копию `report`.
5. Редактирование меняет только рабочую копию.
6. При сохранении/утверждении `ReviewPage` вызывает callback из `main.tsx`, который обновляет сохранённый документ.
7. После сохранения/утверждения выполняется переход на `/report`.

## 7. Валидация

Обязательное содержимое:

- имя кандидата в заголовке;
- направление;
- непустой Markdown каждого из шести разделов.

Остальные реквизиты могут быть пустыми.  
Если дата заполнена, она должна быть корректной.

Ошибки показываются рядом с полями.  
При неудачной отправке фокус переводится на первое ошибочное поле.

## 8. Markdown-рендеринг

Используется общий компонент `MarkdownContent` на базе `react-markdown`.

Требования:

- без `dangerouslySetInnerHTML`;
- без `rehype-raw`;
- стандартная безопасная обработка URL;
- обычные переносы строк не превращаются в `<br>`;
- основные заголовки разделов выводятся приложением, а не хранятся в Markdown.

## 9. Источники разделов

Каждый раздел имеет `sourceEntryIds: string[]`.

Источники привязаны к разделу, а не к отдельным предложениям.  
При нажатии на кнопку «Источники раздела · N» раскрывается блок с вопросами и полными ответами.

## 10. Ограничения

- Нет сохранения между перезагрузками страницы.
- Нет backend, API, БД, LLM, 1С.
- Нет авторизации.
- Нет отдельной формы решения «Принять / Отказать».
- Нет автоматической проверки согласованности статуса, выводов и вердикта.
